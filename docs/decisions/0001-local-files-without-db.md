# ADR-0001: Хранить данные «Рецептуса» в локальных файлах без СУБД

## Контекст и постановка задачи

SRS версии 0.1 требует работу офлайн и сохранение продуктов, категорий и рецептов между запусками (REQ-FUNC-007, REQ-INT-003). Нужно выбрать способ постоянного хранения на ПК пользователя.

Вопрос: использовать встроенную/локальную СУБД или файлы в каталоге пользователя?

## Драйверы решения

* Соответствие границам SRS: без СУБД и без сети
* Простота установки для домашнего пользователя
* Учебный объём и сроки курса
* Достаточная надёжность для объёма ≤ 500 продуктов и ≤ 200 рецептов (REQ-PERF-001)

## Рассмотренные варианты

* Локальные структурированные файлы (JSON) в каталоге пользователя
* Встраиваемая СУБД (SQLite / H2)
* Только оперативная память без сохранения

## Итог решения

Выбранный вариант: «Локальные структурированные файлы (JSON) в каталоге пользователя», потому что он напрямую удовлетворяет REQ-INT-003 (СУБД не подключается) и закрывает REQ-FUNC-007 без серверной инфраструктуры.

### Последствия

* Хорошо, потому что установка не требует настройки БД
* Хорошо, потому что проще объяснить заказчику и проверяющему
* Плохо, потому что при росте объёма и сложных запросах файлы менее удобны, чем SQL
* Нейтрально, потому что для версии 0.1 объём данных мал

### Подтверждение

В коде нет JDBC/ORM-зависимостей на СУБД; интеграционный тест проверяет сохранение и чтение после перезапуска (матрица SRS, REQ-FUNC-007).

## Плюсы и минусы вариантов

### Локальные файлы JSON

* Хорошо, потому что соответствует запрету СУБД в SRS
* Хорошо, потому что данные читаемы и легко резервируются копированием папки
* Плохо, потому что нет транзакций СУБД «из коробки»

### Встраиваемая СУБД

* Хорошо, потому что удобные запросы и целостность
* Плохо, потому что противоречит явному ограничению SRS 0.1
* Плохо, потому что усложняет поставку и объяснение границ

### Только память процесса

* Хорошо, потому что просто реализовать
* Плохо, потому что ломает REQ-FUNC-007

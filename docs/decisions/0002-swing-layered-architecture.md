# ADR-0002: Java + Swing и слои UI / Domain / Persistence

## Контекст и постановка задачи

Тема курса задаёт desktop-приложение на Java. Нужно выбрать GUI-стек и способ организации кода так, чтобы закрыть экраны из SRS и сохранить сопровождаемость.

Вопрос: какой UI-фреймворк и какая структура модулей для «Рецептуса» 0.1?

## Драйверы решения

* Соответствие языку темы (Java)
* Локальный GUI без браузера и сервера
* Разделение интерфейса и правил подбора рецептов
* Ограниченные сроки учебной итерации

## Рассмотренные варианты

* Java Swing + три слоя (UI / Domain / Persistence)
* JavaFX + три слоя
* Монолитный класс «всё в одном окне» без слоёв

## Итог решения

Выбранный вариант: «Java Swing + три слоя», потому что Swing доступен в стандартной поставке, не требует отдельного runtime UI-плагина в учебной среде, а слои позволяют отдельно тестировать `RecipeMatcher` (REQ-FUNC-006, REQ-PERF-001) без окон.

### Последствия

* Хорошо, потому что доменная логика тестируется юнит-тестами
* Хорошо, потому что UI можно менять, не ломая алгоритм подбора
* Плохо, потому что Swing визуально «старее» JavaFX
* Нейтрально, потому что для одного пользователя на Windows этого достаточно

### Подтверждение

Пакетная структура `ui` / `domain` / `persistence`; тесты домена без создания Swing-окон (acceptance criteria SRS 3.5.9).

## Плюсы и минусы вариантов

### Swing + слои

* Хорошо, потому что проще поставить и собрать в Maven-проекте курса
* Хорошо, потому что слои поддерживают трассировку к VIEW-002/003
* Плохо, потому что современный look-and-feel нужно настраивать отдельно

### JavaFX + слои

* Хорошо, потому что современнее визуально
* Плохо, потому что чаще требует отдельной зависимости/настройки runtime
* Нейтрально, потому что слои остаются теми же

### Монолит без слоёв

* Хорошо, потому что быстрее «набросать» прототип
* Плохо, потому что сложно тестировать REQ-FUNC-006 и сопровождать

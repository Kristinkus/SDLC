1 ЦЕЛЬ И ЗАДАЧИ

Цель работы — освоить основные возможности интегрированной среды разработки
IntelliJ IDEA по созданию объектно-ориентированных приложений на языке Java,
освоение сборки и отладки программ с графическим интерфейсом, а также применение
архитектурного шаблона MVC с активной моделью.

В соответствии с заданием необходимо разработать утилиту для конвертации длины
между единицами измерения. Для выполнения работы поставлены следующие задачи:

1. Освоить и настроить проект Java в IntelliJ IDEA, изучить средства редактирования,
   сборки, запуска и отладки;
2. Освоить средства IntelliJ IDEA для работы с UML и SysML v2 и отобразить результаты
   настройки в отчёте;
3. Разработать настольное приложение с главной формой и отдельным окном ввода
   (сигналы Swing);
4. Обеспечить выбор единиц длины (включая «нестандартные»), сохранение последних
   корректных данных и их восстановление при повторном вводе;
5. Реализовать проверку входных данных и вывод понятного сообщения об ошибке;
6. Разделить приложение на модель, представление и контроллер и реализовать
   активное уведомление представления моделью;
7. Проверить основные сценарии работы программы и подготовить ответы
   на контрольные вопросы.


2 КРАТКИЕ ТЕОРЕТИЧЕСКИЕ СВЕДЕНИЯ

2.1 Интегрированная среда разработки и её компоненты

IDE представляет собой комплекс инструментов: редактор кода, средства навигации и рефакторинга, подсистему сборки и запуска, отладчик, терминал, а также поддержку систем контроля версий. IntelliJ IDEA в процессе набора кода выполняет его статический анализ, подсвечивает ошибки и предупреждения, предлагает quick-fix и даёт возможность запускать метод main прямо из редактора.

2.2 Редактирование и навигация в IntelliJ IDEA

В редакторе доступны автодополнение, автоматический импорт, выравнивание кода, переименование с учётом всех ссылок и поиск мест использования. Переход к определению выполняется сочетанием Ctrl+B, поиск использований – Alt+F7, форматирование – Ctrl+Alt+L, список намерений и быстрых правок – Alt+Enter. Дерево файлов проекта видно в окне Project, а вывод сборки и работы программы – в Build и Run.

2.3 Сборка, запуск и отладка Java-приложения

Компилятор javac переводит исходники Java в байт-код виртуальной машины. В IntelliJ IDEA сборка выполняется через Build Project; для класса Main создаётся конфигурация, которую запускают командами Run или Debug. Breakpoint ставится кликом слева от нужной строки либо через Ctrl+F8. В режиме отладки доступны стек вызовов и текущие значения переменных; пошаговое выполнение обеспечивают Step Over, Step Into и Step Out.

2.4 Паттерн MVC

Архитектура MVC выделяет три роли. Model отвечает за данные и логику перевода длины из одних единиц в другие. View отвечает за окна Swing и показ исходных значений вместе с результатом. Controller реагирует на нажатия и ввод пользователя – открывает диалог, парсит число и выбранные единицы, затем вызывает методы модели. За счёт этого расчёт можно тестировать отдельно от графической части.

2.5 Активная и пассивная модель

При пассивной модели после изменения данных контроллер сам просит View обновиться. Активная модель сама оповещает слушателей, что состояние изменилось. В утилите «Высота и длина» класс LengthModel реализован как активная модель: применяется Observer через вложенный интерфейс ModelListener. Когда конвертация завершена успешно, вызывается notifyListeners(), после чего MainView в onModelChanged() перерисовывает подписи с новым результатом.


3 ХОД ВЫПОЛНЕНИЯ ЛАБОРАТОРНОЙ РАБОТЫ

3.1 Постановка задачи
Разработана утилита, которая принимает длину, исходные единицы измерения и целевые
единицы, после чего выполняет конвертацию. На главной форме размещена кнопка
«Ввести данные», открывающая модальное окно InputDialog.

Поддерживаемые единицы:
- дюйм (0,0254 м);
- ярд (0,9144 м);
- сантиметр (0,01 м);
- метр (1 м);
- американский таракан (≈ 0,04 м);
- шея жирафа (≈ 2 м);
- самая длинная змея (≈ 10 м);
- человеческий язык (≈ 0,10 м);
- футбольное поле (≈ 105 м).

Контекстные данные восстанавливаются моделью: при повторном открытии окна
подставляются последние успешно обработанные значения.

3.2 Настройка среды и плагины для UML и SysML v2
В IntelliJ IDEA создан Maven-проект с каталогом src/main/java и пакетом
lab_lcdsw.high_length. В качестве Project SDK выбран JDK 17. Класс
lab_lcdsw.high_length.Main содержит метод main и используется в конфигурации запуска.
Для UML применён плагин PlantUML Integration и файл docs/mvc.puml. Для материала
SysML v2 используется текстовый фрагмент docs/sysml_v2.txt.

Представление системы в нотации, близкой к SysML v2:

package LengthConverter {
  part def LengthModel;
  part def MainView;
  part def InputDialog;
  part def LengthController;
  part application {
    part model : LengthModel;
    part view : MainView;
    part dialog : InputDialog;
    part controller : LengthController;
    connect view to controller;
    connect controller to model;
    connect model to view;
  }
}

3.3 Использование отладчика
Точка останова устанавливается в методе convert класса LengthModel. В окне Debug
просматриваются переменные meters и результат деления, проверяется точность
вычисления через Evaluate Expression.

3.4 Структура проекта и каркас MVC с активной моделью
Проект разделён на следующие компоненты:
- LengthUnit — перечисление единиц и эталонных длин в метрах;
- LengthModel — хранит данные и результат, содержит логику конвертации и механизм
  уведомления слушателей;
- MainView — главный интерфейс, реализует LengthModel.ModelListener для
  автоматического обновления при изменении модели;
- InputDialog — модальное окно для сбора данных;
- LengthController — обрабатывает ввод пользователя, выполняет парсинг строк
  в числа и передаёт команды в модель;
- Main — точка входа, инициализирующая компоненты.

3.5 Модель
LengthModel реализует активную модель. Метод setData выполняет валидацию:
проверка конечности числа и неотрицательности длины, проверка выбранных единиц.
После валидации вызывается convert(), результат сохраняется, затем вызывается
notifyListeners().

3.6 Представление
MainView отображает введённые данные и результат конвертации. Благодаря реализации
интерфейса ModelListener метод onModelChanged обновляет текстовые метки автоматически
после того, как модель зафиксировала изменение. InputDialog обеспечивает ввод длины
и выбор единиц, поддерживает Enter и кнопку OK.

3.7 Контроллер
LengthController управляет жизненным циклом InputDialog и отвечает за преобразование
пользовательского ввода из текстового формата к числам и enum. В случае
NumberFormatException или IllegalArgumentException контроллер перехватывает ошибку
и выводит её пользователю через JOptionPane.

3.8 Валидация данных и обработка ошибок
Приложение предотвращает ввод некорректных данных. Сообщения об ошибках
(например, «Длина не может быть отрицательной!») формируются в модели и передаются
через контроллер во View. Восстановление данных реализуется через метод
inputDialog.setValues(), который вызывается перед показом окна.

5 ОТВЕТЫ НА КОНТРОЛЬНЫЕ ВОПРОСЫ

Вопрос 1. Каков минимальный состав IDE?
В состав IDE входят редактор кода, средства для навигации, система сборки и запуска,
отладчик, средства навигации и рефакторинга, терминал, интеграция и система контроля
версий и механизм плагинов. В IntelliJ IDEA основные рабочие окна называются Project,
Build, Run, Debug, Problems и Terminal.

Вопрос 2. Каковы основные виды работы с редактором кода?
К основным приёмам относятся автодополнение, быстрые исправления, автоматический
импорт, форматирование, переход к объявлению, поиск использований, переименование,
просмотр иерархии классов и анализ предупреждений.

Вопрос 3. Каким образом выполняется сборка и запуск проекта?
IntelliJ IDEA компилирует Java-файлы командой Build Project. Для запуска выбирается
класс Main с методом public static void main(String[] args) и выполняется команда Run.
При запуске в режиме Debug программа работает под управлением отладчика и останавливается
на активных точках. Проект также можно собрать командой mvn compile и запустить
командой mvn exec:java.

Вопрос 4. Что такое MVC?
MVC — архитектурный шаблон, который разделяет данные и предметную логику, графический
интерфейс и обработку действий пользователя. В данной работе роль модели выполняет
LengthModel, роль представления — MainView и InputDialog, а роль контроллера —
LengthController.

Вопрос 5. Чем отличается активная модель от пассивной?
Пассивная модель не уведомляет представление, поэтому после её изменения контроллер
должен отдельно обновить интерфейс. Активная модель публикует событие об изменении
своего состояния. В приложении LengthModel вызывает notifyListeners(), а MainView
получает новое состояние через метод onModelChanged и самостоятельно обновляет метки.
